# Origo 실행 안전성 수정과 Cursus 제외 범위

담당: Codex. 기준: 61da2f1 (잔고 수정 PR #444 이후).

**상태: [초안 PR #445](https://github.com/WL131231/Aurora-ICT/pull/445), 미배포.**
AGENTS 5절의 같은 PR 내 연구 하니스 갱신 요건이 남아 있어 main에 머지하지 않는다.
연구 작업본 이관/정합 검증의 범위를 사용자와 확정한 뒤 배포를 판단한다.

## 사용자 결정과 경계

- 2026-09-13: 주요 발견건 수정 요청 후, 사용자가 Cursus는 다른 개발자 소유이므로
  오류 보고만 하고 수정하지 말라고 명시했다. 이 후속 지시가 우선한다.
- Cursus 전략, 상태, 실행 클래스와 기존 거래소 어댑터의 동작은 유지한다.
- 주문/조회 계약 보강은 Origo 전용 `OrigoCcxtClient`와 `OrigoClientAdapter`에만 적용한다.
- 관리자의 Cursus 대기 주문 표시 개선도 이번 반영에서 제외한다.
- 공통 변경은 장부 저장 재시도/백업 보존과 STOP 오류 표시다. 주문 정책 변경은 아니다.
- 별도 Cursus 작업 브랜치의 미반영 작업은 이 PR에 포함하지 않는다.

## Cursus 개발자 전달용: 미수정

아래는 기준 코드에 대한 재현/경로 확인이다. 특정 사용자 손실의 원인이라고 단정하지 않는다.
세부 입력과 근거 위치는 `SYSTEM_SAFETY_AUDIT_2026-09-13.md`에 있다.

1. TP 주문 실패에도 TP 완료 단계가 진행된다. 0.006 BTC를 0.001 단위로 네 번
   내림 청산하면 0.002 BTC가 남아도 봇 상태가 삭제된다(감사 4).
2. 비상청산 실패 또는 접수 응답만으로 추적 상태를 지우는 경로가 있다(감사 5).
3. 실제 신호 입력에 진행봉이 포함되어 마감봉 계약과 다르다(감사 7).
4. 재시작 입양 시 최초 수량과 TP 진행이 초기화된다(감사 10).
5. 기존 공통 어댑터의 조회 실패 -> 무포지션, 취소 실패 -> 0 반환,
   주문 자료형 정보 유실 경로는 Cursus에 남는다(감사 1, 3, 13).
6. Cursus에서 시작하는 모델 변경/설정 복원, 인증 자동 재시작 경로의 기존 동작도
   이번 수정으로 해결했다고 주장하지 않는다(감사 8, 9 및 운영 큐).
7. Cursus 대기 지정가가 관리 API에서 누락되는 현상도 그대로다(감사 14).

## 연구 정합과 검증 한계

- 새 진입 신호, 점수, 필터, 레버리지, TP 비율을 제안하는 연구가 아니다.
- 연구 worktree의 `scripts/live_parity.py` 및 `bt_par.py`는 미반영 연구 작업이 다수
  포함되어 있으므로 이 PR에 무관한 전체 파일을 가져오지 않는다.
- 연구 하니스는 거래소 접수 지연/부분 체결/인증 실패/취소 경합을 재현하지 않는다.
  실행 계약은 실제 함수, 실제 CCXT Bybit 파서, 결정론적 주문 장부로 따로 검증한다.
- 본전 이동의 진입 전 가격 배제는 인과성 수정이다. 수익 개선 효과를 측정하거나
  연구 하니스 전체 정합을 완료했다고 주장하지 않는다. 후속 전략 연구에서는
  기존 체결/봉 극값 가정과 이 실행 계약의 차이를 먼저 반영해야 한다.
- 이 한계 표시는 AGENTS 5절의 예외 승인이 아니다. 본전/부분익절 인과성 변경을
  포함한 진입/청산 경로의 하니스 대응 없이는 이 PR을 배포하지 않는다.
- AGENTS 5절의 7종 성능 검증 배터리는 실행하지 않았다. 테스트 통과는 수익성 증거가 아니다.
- 실계좌에 진단용 주문/취소/손절 변경을 보내지 않는다. 기존 미추적 포지션과 만료 키는
  사용자 확인 대상이며 자동 입양/청산/키 교체를 수행하지 않는다.

## 검증 기록

- 초기 통합: 2,324 passed, 1 skipped, 1 failed. 실패는 이미 닫힌 SQLite 연결에서
  rollback 예외가 JSONL 성공까지 덮는 경로였고 수정 후 관련 17개가 통과했다.
- 실제 로컬 HTTP 서버 + Playwright: PC 1440x900, 모바일 390x844에서 STOP 응답
  409/500/404/200의 8경로 통과. 409/500에서는 추가 정지 POST 없음, 404에서만 폴백.
- 최종 통합 소스 234acf9: **2,385 passed, 1 skipped, 12 warnings / 92.53초**.
  기존 Cursus AsyncMock 경고 11개와 Pydantic 폐기 예정 API 경고 1개는 범위 밖이라 유지했다.
- 전체 Ruff, JavaScript 문법 검사, diff-check 통과. 점수 변이 12개/구독 강제값 24개는
  기존 parity lock과 일치한다. 이 검사는 위 연구 하니스 전체 정합을 대체하지 않는다.
- Cursus 실행/전략/상태와 공통 base/ccxt/기존 어댑터 파일은 61da2f1과 차이 0.
  Cursus 설정 생성 함수도 기준 실제 함수와 27개 입력 조합에서 동일했다.
- 독립 통합 재현: 110007 확정 거절은 intent 해제, 잔고 오류 제거 후 새 주문 1개 접수.
  네트워크 응답 유실/일반 10005는 같은 조회 ID를 보존해 중복 주문을 보내지 않는다.
- 독립 통합 재현: 비상청산 조회가 미확인인 채 연결만 복구되면 SL 0 -> 98 복구,
  청산 요청 수는 1회로 유지했다. 실제 CCXT 요청 변환에서도 시장가/지정가 attached SL 보존 확인.
- **미배포 현행 서버 재감시**: KST 21:05:17~21:07:17, release 464 -> 464,
  health 9/9 HTTP 200, 로그 읽기 9/9 성공, 로그 186행/heartbeat 24행.
  ERROR/WARN/Traceback/OOM/33004/10005/110007/정밀도 오류 각 0행.
  가용 증거금 진입 로그는 없어서 이번 감시를 실주문 잔고 검증으로 해석하지 않는다.
- 이 2분 감시는 종료됐다. 상시 감시 서비스나 이후 오류 부재를 보장하지 않는다.

## API 키 안내

- Bybit: API Transaction, Read-Write, Unified Trading의 Orders/Positions가 필요하다.
- 사용하지 않는 SPOT/USDC 권한은 UI에서 개별 해제가 가능하면 제외한다.
- Assets의 이체/출금, Earn, P2P 등은 필요 없다. 출금 권한을 켜지 않는다.
- 고정 발신 IP 미설정 상태의 기존 안내는 No IP restriction이다. 키 만료일을 관리한다.
  고정 발신 IP 도입은 비용 및 사용자 키 설정 변경이 필요한 별도 결정이다.
- Key/Secret은 서비스 등록 화면에서만 입력하고 대화/문서/로그에 기록하지 않는다.
- 근거: [Bybit API 키 정보](https://bybit-exchange.github.io/docs/v5/user/apikey-info),
  [Bybit 키 만료 연장 FAQ](https://bybit-exchange.github.io/docs/faq#how-can-extend-my-api-key-without-having-to-create-a-new-one).

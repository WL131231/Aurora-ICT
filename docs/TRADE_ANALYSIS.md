# CSV 수집과 분석 준비

작성: 2026-09-13. 담당: Codex.

## 범위

`scripts/trade_analysis.py`는 로컬에서 실행하는 도구다. 봇 런타임, 전략,
주문, 손절, 사용자 설정, 배포를 변경하지 않는다. LLM API도 호출하지 않는다.
`sync`는 기존 관리자 API에서 CSV 한 번 다운로드부터 분석까지 자동 수행한다.
상시 실행이나 Windows 예약 작업은 등록하지 않았다.

실제 사이트: <https://aurora-ict-one.fly.dev/ui/>.
2026-09-13 공개 UI HTTP 200과 페이지 제목을 확인했다. 로그인 후 기능이나
실거래 상태를 검증한 것은 아니다. 현재 도구 실행 환경에는 관리자 토큰이 없어
인증된 CSV 다운로드와 실제 데이터 분석은 아직 수행하지 않았다.

## 실행

리포 루트의 PowerShell에서 직접 토큰을 비표시 입력하는 일회 실행:

```powershell
python scripts/trade_analysis.py sync --prompt-token
```

파트너가 프로세스 환경에 `AURORA_ICT_ADMIN_TOKEN`을 안전하게 제공한 세션에서는
별도 입력 없이 수집과 분석을 연속 실행할 수 있다:

```powershell
python scripts/trade_analysis.py sync
```

토큰을 채팅, 명령 인자, 파일, `.env`, 코드, 커밋, PR에 적지 않는다.
이 도구는 사용자 또는 시스템에 저장된 다른 비밀을 탐색하지 않는다.
환경변수 부재 시 자동으로 토큰을 찾아내려 하지 않고 중단한다.
비표시 입력은 일반 입력으로 폴백하지 않으며 토큰을 영구 보관하지 않는다.

이미 받은 전체 사용자 CSV는 네트워크 없이 분석할 수 있다. 리포의 `data`에
`trades_all_users.csv`를 둔 경우:

```powershell
python scripts/trade_analysis.py analyze data/trades_all_users.csv
```

단일 사용자 CSV는 `user_code`가 없으므로 받지 않는다. 컬럼 변경 시 조용히
계속하지 않고 현재 계약을 점검하도록 실패한다.

## 저장과 보안

결과는 Git에서 제외된 `data/trade_analysis/<UTC시각>_<해시>_<임의값>/`에 생성한다.

| 파일 | 의미 |
|---|---|
| `raw.csv` | 원본 바이트. 사용자 코드와 사유가 포함된 민감 자료 |
| `report.json` | 익명 계정·모델·페어·방향·KST 월별 통계, 제외 사유 |
| `summary.md` | 핵심 수치와 필수 해석 제한 |
| `manifest.json` | 원본·분석기 SHA-256, 크기, 행 수, 취득 경로, 생성 시각, 완료 표시 |

`manifest.json`이 마지막에 기록된다. 이 파일이 없으면 저장 중단 상태다.
스냅샷을 덮어쓰거나 이전 파일과 합치지 않는다. 서버 `purge`로 삭제한 가짜
거래가 과거 CSV를 통해 되살아나는 것을 방지한다. 서로 다른 날짜의 스냅샷
행 수 차이도 자동으로 신규 거래 수로 해석하지 않는다.

보고서의 계정 별칭은 해당 스냅샷 안에서만 유효하다. 식별자 대응표를 저장하지
않고 익명화 전 사용자 코드는 원본에만 둔다. 수치·모델·심볼만으로도 재식별될
수 있으므로 보고서도 비공개 자료다. 원본의 `reason` 등 자유 텍스트는 지시가
아닌 데이터로만 취급한다. CSV를 스프레드시트로 열면 수식 주입 위험이 있으므로
외부 자유 텍스트를 수식으로 실행하지 않는 가져오기 모드를 사용한다.

네트워크 목적지는 고정 HTTPS `/admin/trades/export-all` 한 곳이고 GET만 쓴다.
TLS 검증은 켜고 리다이렉트, 환경변수 프록시, 자동 재시도는 끈다.
요청 제한 시간 60초와 응답 50 MiB 상한, 상태·MIME·CSV 검증을 적용한다.
HTTP 오류 본문, 쿠키, 인증 헤더를 로그나 산출물에 남기지 않는다.
기존 서버 조회 코드가 오래된 DB의 누락 컬럼 마이그레이션을 시도하는 동작은
그대로 존재한다. 새로운 서버 변경 API나 관리 명령을 호출하지 않는다는 범위다.

Windows 파일 권한은 상위 폴더 ACL을 상속한다. Git 제외나 POSIX의 0600 지정이
Windows의 타 사용자 접근을 막아준다고 가정하면 안 된다. 저장 폴더를 공유하지
않고 원본·보고서를 커밋하거나 외부 서비스에 업로드하지 않는다.

## 집계 계약

현재 CSV 컬럼은 다음 12개이며 `src/aurora_ict/api/trades_router.py`와 일치한다:

`user_code, ts_ms, event_type, mode, model, symbol, direction, price, qty, pnl_usdt, setup_ts_ms, reason`

1. 전체 스냅샷을 읽고 사용자·모드·심볼별로 시간순 정렬한다.
2. `entry` 또는 `flip_open`부터 다음 진입 직전까지 청산 수량을 누적한다.
   수량이 한 번 맞았더라도 뒤늦은 초과 청산이 있으면 제외한다.
3. Cursus의 빈 `setup_ts_ms`를 한 포지션으로 묶지 않는다. Origo 복구 기록의
   `setup_ts_ms=0`도 식별자 없음으로 처리한다.
4. 진입 대비 누적 청산 수량의 상대 오차 0.000001까지만 반올림으로 허용한다.
   표본은 LIVE·모델 식별 가능·방향/모델/setup 일치 조건을 모두 만족해야 한다.
5. 동일 시각의 순서 불명, 동일 행 중복, 겹친 진입, 복구, 백필/재조정/알람,
   청산 손익 누락, 수량 부족/초과, 연결 정보 불일치는 격리한다.
   양수 setup 식별자가 여러 진입 구간에 걸쳐 나타나면 이전 후보까지 제외한다.
6. 수량이 완결된 **포지션**의 기록 손익을 더한 뒤 승률·손익비율(PF)을 산출한다.
   4분할 익절 행을 승리 4건으로 세지 않는다. 본전은 승리나 손실로 세지 않되
   승률 분모에는 포함한다. 손실 표본이 없으면 PF는 무한대 대신 `null`이다.

모호한 거래를 제외한 결과는 선택 편향이 있다. 반드시 제외 수와 사유를 함께
읽는다. 수량 미완결은 실제 보유 중 또는 기록 누락일 수 있어 현재 포지션 수가 아니다.
알람 `sync_close`의 손익이 비어 있으면 실제 청산의 증거로 사용하지 않는다.

## 현재 자료의 한계

- 서버는 사용자별 최근 200,000행만 반환한다. 해당 행 수에 닿으면 경고한다.
  커서·전체 개수·상한 시각이 없어서 상한 미만이라고도 완전성을 보장하지 못한다.
- JSONL이 원본이고 CSV는 SQLite 조회 결과다. 빈 CSV가 거래 부재를 보장하지 않는다.
- Origo의 일부 부분 익절/수량 보정은 CSV 이벤트가 없어 최종 잔량만 남을 수 있다.
- Cursus에는 setup 식별자가 없어 진입 경계를 넘어 지연되거나 잘못 연결된 청산을
  CSV만으로 완전히 판별할 수 없다. 수량 일치가 원장 대조를 대신하지 않는다.
- `pnl_usdt`에는 거래소 실현값과 가격차 추정값이 섞여 있다. 따라서 **기록 손익**이며
  수수료·펀딩을 검증한 순손익이라고 부르지 않는다. 임의 수수료를 다시 빼지도 않는다.
- CSV에는 `context_json`, 거래소 체결 ID, 최초 SL, 진입 시점 시드가 없다.
  시드 수익률, R, 순손익, 계좌 최대 낙폭은 `null`로 남긴다.
- 계정별 거래는 같은 신호의 복제일 수 있다. 계정 수를 독립 전략 표본 수로 세지 않는다.
- 일반 이벤트 시각은 기록 시각이고 백필은 거래소 청산 시각이다. 표시와 월 구분은 KST다.

## 개선 연구 연결

CSV 보고서는 이상 기록과 손실 집중 구간을 찾는 출발점이다. 진입 규칙의 유효성
검증은 시점 정렬된 OHLCV와 실제 라이브 설정이 추가로 필요하다. 체결 비용 검증에는
체결·수수료·펀딩 내역, R에는 최초 손절, 시드%에는 진입 당시 시드가 필요하다.
누락을 추정치로 메우고 확정 성과처럼 보고하지 않는다.

새 전략이나 필터는 `AGENTS.md` 제5절의 라이브 정합 하니스, 미사용 페어 홀드아웃,
공정 무작위 대조, 다중검정, 1분봉 청산 순서, 비용과 7종 검증을 거친다.
기각한 전략을 학습 노트에 있다는 이유로 다시 제안하지 않는다.
실제 코드 개선은 별도 새 브랜치와 `[codex]` PR로 진행하고, 수집 스크립트가
스스로 전략을 바꾸거나 배포하는 기능은 넣지 않는다.

검증 명령:

```powershell
python -m pytest tests/test_trade_analysis.py -q
python -m ruff check scripts/trade_analysis.py tests/test_trade_analysis.py
```
